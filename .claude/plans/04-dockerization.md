## Why Docker Is Needed

- The Flask dev server (`app.run`) is single-threaded and not safe for production
- Azure Container Apps requires a container image to deploy
- gunicorn serves the app on `0.0.0.0:5000` so the container port is reachable from the host

---

## `app.py` Changes

```python
# Before
if __name__ == "__main__":
    app.run(debug=True, port=5001)

# After
if __name__ == "__main__":
    port = int(os.environ.get("PORT", 5000))
    app.run(host="0.0.0.0", port=port, debug=True)
```

- `host="0.0.0.0"` — binds to all interfaces inside the container (required for Docker networking)
- `PORT` env var — Azure Container Apps injects `PORT` at runtime
- Default `5000` — consistent with the Dockerfile `EXPOSE 5000`
- `if __name__ == "__main__":` guard preserved — pytest imports `app` directly without triggering `app.run()`

---

## Dockerfile

```dockerfile
FROM python:3.12-slim

WORKDIR /app

COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

COPY . .

EXPOSE 5000

CMD ["gunicorn", "--bind", "0.0.0.0:5000", "app:app"]
```

- `python:3.12-slim` — minimal image, no dev tools
- `requirements.txt` copied first — Docker cache layer reused on code-only changes
- gunicorn entry point — production WSGI server
- `app:app` — module `app`, Flask instance `app`

## .dockerignore

Excludes from build context:
- `.git`, `.github`, `.claude` — version control and IDE files
- `ezfit/` — local Python venv (300MB+)
- `__pycache__/`, `.pytest_cache/`, `*.pyc` — generated bytecode and test cache
- `.DS_Store`, `.env` — macOS metadata and secrets
- `tests/` — test suite not needed in production image
- `images/`, `database/` — unreferenced assets and placeholder stub
- `README.md`, `prompt` — docs not needed at runtime

## Commands

### Build

```bash
docker build -t ezfit .
```

### Run

```bash
docker run --rm -p 5000:5000 ezfit
```

If port 5000 is already in use locally, map to another host port:

```bash
docker run --rm -p 5001:5000 ezfit
```
